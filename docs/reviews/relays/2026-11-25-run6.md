## Questions

Questions marked "Kiro is unsure" are Kiro's own doubts.

### Milestone 1: do the R5 repairs hold?

- For each of R5-1 to R5-13: is it resolved, partly resolved or not resolved?
- **R5-1 and R5-9 (spans).** A span must keep at least one saved neighbouring line,
  and an unlocated change owns the region between its neighbours. Can either rule
  still rewrite the wrong lines, or block an edit it should allow?
- **R5-2 (group decisions).** Recovery checks a saved group decision against the
  files first. Can a member changed while Nexus was closed still be decided wrongly?
- **R5-3 (evidence).** Facts are checked against the cited record's fields. **Kiro is
  unsure** whether this now demotes correct answers that a real model phrases
  differently from the double.
- **R5-5 and R5-6 (the delivery log).** A damaged log stops delivery until it is
  repaired, or replaced on request with a time boundary. Is the user told clearly, and
  can `prunedUpTo` still let an occurrence repeat?
- **R5-8 (scope).** An Edit may change only the raw lines a read returned, read in
  parts with `fromLine`. Can a proposal still reach a line the run was not shown?

### Milestone 2: appearance

- The service writes the stored preference into the unauthenticated app shell as
  attributes on `<html>`, and `/theme-boot.js` sets the theme before the first paint.
  Is anything there a leak or an injection risk? The values come only from a Zod
  enum.
- **Kiro is unsure:** from Match system, the quick switch chooses the opposite theme
  as an explicit mode, so the user leaves Match system with one press. Is that
  clear enough on screen?
- The preference is per profile, and a change reaches every open session through
  `appearance.changed`. Is changing another tab's theme acceptable?
- Electron main reads `appearance.json` directly, only to choose the window's
  first colour. Is that a sound exception to "everything through the service"?
- The contrast tests compute text, control-edge, focus and state pairs from the real
  stylesheets for all six palettes. Which pair that matters do they miss?
- Four approved light values moved slightly so every pair passes (DEC-028). Is any
  difference from the approved wireframe visible?

### Milestone 3: the correction loop

- **Binding.** A correction is bound to the rejected change through
  `correctionRunId`, and may propose one operation on the same target. For notes,
  "the same target" means lines that overlap where the rejected change's original
  lines now are. Can a correction write anywhere else?
- **Once only.** A synchronous admission set and `beginCorrection` each stop a second
  run. Can two tabs, a retry and a restart still produce two corrections, or none
  when one was asked for?
- **Supersede last.** Can a crash leave a change `superseded` with no correction, or a
  correction whose change is still `rejected` after recovery?
- **Kiro is unsure:** the reason goes to the model verbatim as "the user's own
  words". Scope is enforced in code, but is there a way for that text to widen what
  the run may do?
- **Behaviour change.** After any rejection, the review bar now stays on the rejected
  change's page until the reason is sent or skipped (before, it moved on at once). Does
  this break any other flow, for example the fixed demo, or a rejected new issue?
- Corrections of new issues and links keep the reason only. Is that acceptable for
  now?

### Milestone 4: backlinks and completion

- **Resolution (DEC-030).** A path or file name; the closest note by shared leading
  folders, then fewest folders; a tie is ambiguous. Can you construct a link that the
  preview, the backlinks and completion treat differently?
- Links in fenced code and inline code are ignored. **Kiro is unsure:** links in
  indented code blocks are not ignored, although the preview renders them as code.
- Backlinks are computed from every note on each request. Is that acceptable at the
  sizes a student team would reach?
- **Kiro is unsure:** the completion uses the textarea's own role with
  `aria-autocomplete`, `aria-controls`, `aria-activedescendant` and a polite status,
  not `role="combobox"`, which does not fit a multi-line field. Does a screen reader
  announce the options well?
- Insertion uses `document.execCommand("insertText")`, which is deprecated, to keep
  the browser's undo; it falls back to `setRangeText`. Is that acceptable in Edge
  and Electron?
- A backlink opens its source at the line of the link on disk. If the source note
  has an unsaved draft, the line may differ. Is that acceptable?
